# D01 — packaged local text inference

Scope: the first milestone in `../ai-integration/prompts/01-desktop-companion.md`. No D02–D05 functionality is included. `journal/` remains the authoritative Flutter app and is unchanged. `old/` was not inspected or modified.

## Implementation

- `src/main.cjs`: window, static custom protocol, native file chooser, explicit IPC authorization and quit cleanup.
- `src/preload.cjs`: six named operations plus state/token subscriptions. No generic IPC or filesystem bridge.
- `src/runtime.cjs`: one loaded model, one operation at a time, truthful readiness, timeout/recovery and idle-worker monitoring. The SDK's separate Bare process owns native inference; a second application worker abstraction is unnecessary for this slice.
- `src/model.cjs`: one immutable model definition, explicit HTTPS provisioning, full size/SHA-256 verification on each load, and an atomically replaced model-selection JSON file. No content database is needed.
- `src/renderer/`: plain HTML, CSS and JavaScript. No renderer framework, build pipeline or remote asset dependency is needed for one screen. Model text uses `textContent`, never HTML parsing.

The runtime selects `llamacpp-completion`, Metal GPU inference, a 4,096-token context and a 192-token output limit. Input is limited to 2,000 UTF-8 bytes. Requests are independent, without persistent KV caches or conversation history. A successful native load is required for ready; a remembered path alone never establishes readiness.

The SDK is initialized only after an explicit provisioning/selection or cold load of a previously selected model. All inference uses an absolute local path and `seed: false`. The application never calls the registry or opens SDK administration endpoints. Its own QVAC cache/config lives under app `userData`. Prompts/results have no persistence or telemetry. Model/SDK errors are mapped to bounded recovery messages so raw paths or prompt text do not enter UI diagnostics.

## Security and platform decision

The renderer uses `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, `webSecurity: true` and a restrictive CSP (`connect-src 'none'`). Remote requests, permissions, popups, navigation and webviews are denied. IPC verifies the window, main frame and exact trusted document URL, and validates input in the main process. There is no arbitrary path input over IPC; the OS picker supplies paths.

The current official Electron tutorial includes a development `--no-sandbox` suggestion for Linux without a configured SUID helper. This project never uses that flag. Linux is unsupported initially; no claim is made that the Linux native worker/sandbox combination was resolved or tested. macOS arm64 is the only packaged target. Other platforms are blocked by the app as well as omitted from the build scripts.

QVAC's Forge plugin forces non-ASAR output and rejects universal macOS builds. Native addons and the generated worker are real unpacked resources; only the completion plugin is selected. The resulting preview is unsigned and unnotarized. Signing, installation/update testing and broader distribution remain a later release gate.

## Reproduce the packaged demonstration

```sh
npm ci
npm test
npm run package
# Empty evidence directory: downloads via the actual screen's explicit button.
npm run verify:packaged -- /absolute/path/to/d01-evidence --provision
# Cold restart of the same packaged binary/data, IPv4 and IPv6 blocked by macOS.
npm run verify:packaged -- /absolute/path/to/d01-evidence --offline
```

The verification runner starts the binary with `/private/tmp` as working directory to catch accidental dependence on the source checkout. `sandbox-exec` denies IP ingress/egress for the main process and the Bare inference worker; Unix-domain IPC remains permitted. An external literal-IP probe must fail in the offline run. Exact Electron Helper executables are exempt from inheriting that test profile so Chromium can initialize its own sandbox (macOS rejects nesting these profiles). Renderer requests are separately denied by the application's CSP and session policy. `/bin/ps` is also exempt solely for the harness's fixed process-inspection calls. No inference/download executable is exempt. This proves model loading/generation without external networking in the inference processes; it is not a claim that every Chromium helper has an OS-level network deny rule. System Wi-Fi, firewall and other apps are unaffected.

The explicit `--verify-d01=/absolute/directory` CLI harness uses isolated app data, executes the real renderer form/IPC and real SDK, saves a synthetic result/screenshot, checks isolation, kills the actual Bare process, recovers, unloads and reloads, then quits. It is unavailable to the renderer. Normal launches do not write prompts/results or screenshots. Reports are `online.json` / `offline.json`; `companion.png` is the generated output screen. The outer runner asserts the last native worker exits after the application quits.

## Evidence and limits

Host: **macOS 26.6.2 (25G83), Darwin 25.6.0, arm64, Apple M5, 24 GiB RAM**. Official minimum target requirement is macOS 14 on Apple Silicon; that minimum OS has not been tested here.

Nine Node tests pass for unsupported hosts, cold missing weights, partial files, matching-size corrupt weights, simulated native load failure, request serialization, simulated in-flight worker failure, input bounds and unload/shutdown. These tests use injected SDK behavior where stated and do **not** prove inference. Forge's native verification confirms all 33 required addons for darwin-arm64.

On **27 October 2026**, the actual packaged app passed online and cold network-blocked runs using the real QVAC native worker and Metal. Electron's embedded Node version was **24.22.0**. Both runs passed input/IPC validation, renderer isolation and sandbox settings, denied renderer requests, a responsive renderer during inference, real streamed completion, unload with worker exit, reload, intentional idle native-worker `SIGKILL`, detection/recovery, clear, and quit with the final worker exited. The offline run also passed the external-IP-unavailable probe. The load's native fit probe reported `MTL0`, 25 GPU layers and a 4,096-token context.

The model was provisioned with the same `src/model.cjs` downloader from a developer command before launching the packaged verification; this run did **not** exercise the packaged Download button. Its first transfer stalled, safely discarded the partial and never became ready; a fresh attempt completed and verified the exact checksum. The reproducible `--provision` command above exercises the renderer Download action on empty data. Do not describe that unrun variant as demonstrated.

The normal packaged app was also opened with fresh user data. Its real native file chooser selected the provisioned GGUF, verified it and reached Ready with Generate enabled. It is left open in that state for review, using the local weights under `desktop/evidence-local/app-data/models/`.

The synthetic request was “Give me three short journal prompts about a peaceful walk.” Actual offline output:

> 1. Write about the sights and sounds you see as you walk through peaceful landscapes.
> 2. Describe the smells and sensations you experience as you walk through serene environments.
> 3. Reflect on the emotions you feel as you walk through a peaceful environment, such as joy or peace.

Compact real-run evidence is in [evidence.json](evidence.json); the screenshot is [d01-companion.png](d01-companion.png). Full local reports and the provisioned weights are in ignored `evidence-local/`. The screenshot/report contain synthetic content only.

Network stalls fail safely and discard incomplete files; a fresh download can be requested. Download resume, cancellation UI, disk-failure injection, model libraries, arbitrary GGUFs, phone networking, journal access, persistent jobs and other AI capabilities are not part of D01. The small model is a feasibility/demo model, not a claim of reliable journal-writing quality. Real unsupported-hardware/native load failures on other machines are not claimed as tested.
